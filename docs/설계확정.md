## 2. 재노출 금지 — 한 번 본 항목은 다시 띄우지 않는다

**문제**: 발주 공고는 마감까지 몇 주씩 유효하다. "유효하면 다음 주에도 수록"하면 지난주에 보고 넘긴 항목을 다음 주에 또 보게 된다. **검토 피로를 매주 재생산하는 구조**라 금지한다.

### 2-1. 누적 id 장부

```
data/seen.json     # { "wb-OP00462021": "2026-08-12", "ted-573325-2026": "2026-08-19", ... }
```

수집기가 매 실행마다 이 장부와 대조한다.

- 장부에 없는 id → 신규. 장부에 `first_seen = 오늘` 기록
- 장부에 있는 id → 기존. 장부의 날짜를 그대로 `first_seen`으로 사용

각 항목에 `first_seen` 필드가 붙는다. 이 값이 화면 필터의 기준이다.

### 2-2. 화면 기본값은 "신규만"

- **기본**: 조회 기간 안에 `first_seen`이 있는 항목만 표시 = 그 기간에 **처음 발견된 것**
- **`전부 보기` 토글**: 마감이 안 지난 기존 발주까지 함께 표시

즉 매주 열면 "이번 주에 새로 뜬 것"만 보이고, 필요할 때만 아직 살아있는 기존 건을 펼쳐 본다.

### 2-3. 기존 설계 유지

- 소스 간 병합(같은 사업이 여러 소스에 잡히면 하나로)
- 사내 게시판 기등록 대조 → `already_posted`

`first_seen`(우리가 처음 본 날)과 `already_posted`(게시판에 이미 올라갔는지)는 다른 축이다. 둘 다 유지한다.

## 3. 고장 감지 — 메일 한 통으로 끝낸다

운영자가 작성자 본인이므로 복잡한 장치를 두지 않는다.

- **알림**: GitHub 기본 워크플로 실패 메일. 수신자는 워크플로를 마지막으로 수정한 계정 = 작성자. **추가 구현 없음**
- **방아쇠**: 수집 결과 **전체 합계가 0건이면 `exit 1`**. 이게 실패 메일을 만드는 유일한 장치다. 빼면 형식 변경·빈 응답 같은 조용한 고장에서 메일이 안 온다
- **소스 단위 0건은 정상 처리.** ADB는 주 2–15건으로 편차가 크고, 특정 소스가 그 주에 0건인 것은 흔하다. 각 수집 함수는 try/except로 감싸 빈 리스트를 반환하고 로그만 남긴다 — 한 소스가 죽어도 나머지는 수집된다
- **화면 표시**: 상단에 `마지막 수집: 2일 전` **한 줄만**. 데이터 신선도를 알리는 용도이지 경고 장치가 아니다

경고 배너, README "고장 시 확인 순서" 섹션은 만들지 않는다.

## 5. 데이터 구조

### 파일 레이아웃

```
data/
  index.json                  # 주차·날짜 목록, last_success, 소스별 상태
  seen.json                   # 누적 id 장부 (id → first_seen)
  tenders/2026-08-24.json     # 주 1회
  news/2026-08-24.json        # 매일
```

### 항목 스키마

```json
{
  "schema_version": 1,
  "id": "wb-OP00462021",
  "kind": "tender",
  "source": "World Bank",
  "type": "입찰",
  "country": "Pakistan",
  "country_ko": "파키스탄",
  "title": "Hiring of ITS Specialist under Karachi Mobility Project",
  "org": "Sindh Mass Transit Authority",
  "budget": { "currency": "USD", "amount": 382000000, "is_project_total": true },
  "published": "2026-08-12",
  "first_seen": "2026-08-12",
  "deadline": "2026-08-31",
  "ref_no": "PK-SMTA-561060-CS-INDV",
  "link": "https://projects.worldbank.org/...",
  "score": 92,
  "already_posted": false
}
```

기사는 `kind: "news"`, `board: "A"|"B"`, `media`(매체명)를 갖고 `deadline`·`budget`·`ref_no`가 없다.

**화면 규칙**: 모르는 필드는 무시, 없는 필드는 기본값. 이것이 버전 관리의 본체이고 `schema_version`은 사람이 나중에 읽기 위한 표시다.

### index.json

```json
{
  "last_success": "2026-08-24T06:12:03+09:00",
  "sources": {
    "ted":       { "ok": true,  "count": 34, "at": "2026-08-24T06:11:12+09:00" },
    "worldbank": { "ok": true,  "count": 61, "at": "2026-08-24T06:11:40+09:00" },
    "adb":       { "ok": false, "count": 0,  "at": "2026-08-17T06:09:55+09:00", "error": "401 Unauthorized" }
  }
}
```

### 중복 제거

- 발주: 참조번호(P번호·OP번호·공고번호)로 확정 비교
- 기사: **URL 정규화**(`utm_*`·`fbclid` 등 추적 파라미터 제거, 프로토콜·`www.` 통일) + **제목 정규화 후 유사도 비교**

기사 중복은 완벽하게 만들지 않는다. 같은 사안을 여러 매체가 쓰면 어느 정도 겹치는 게 정상이고, **최종 필터는 사람**이다. 과잉 설계 금지.

## 6. 화면

- 탭: **발주정보 / 기사**
- 기본값: 발주는 이번 주, 기사는 최근 3일 (날짜별 그룹 표시)
- **기본 필터: 신규만 보기.** `전부 보기` 토글로 유효한 기존 발주 표시
- 기사 노출 상한: **보드별 하루 5건** (A 5 + B 5)
- 날짜 선택: 프리셋 칩(오늘 / 최근 3일 / 이번 주 / 최근 2주 / 직접 선택)
- 정렬: 마감임박순 / 최신순
- URL에 상태 반영 — `?tab=tenders&week=2026-08-24&new=1`
- 항목 버튼 3개: `원문 열기` / `제목 번역`(파파고 URL) / `등록문 복사`(클립보드)
- 상단: `마지막 수집: N일 전` 한 줄

### 6단계 추가 — 국내 동향 스트림 (부서 요구)

한국 ITS **정책·법제도·기술 동향**을 모은다. 기존 Industry Updates(국내 기업 뉴스)와 다른 축이다 — 이쪽은 법 개정·입법예고·정책 발표가 대상이다.

**소스 후보 (실측부터)**

- 대한민국 정책브리핑(korea.kr) RSS
- 국토교통부 보도자료
- 법제처 입법예고
- itskorea 정책 카테고리
- 구글뉴스 한국어에 정책 검색어 세트 추가 — `C-ITS`, `자율주행 법안`, `지능형교통체계`, `도로교통법 개정`, `모빌리티 정책` 등

**원칙 유지**: API 키 0개. 공공데이터포털처럼 키 신청이 필요한 소스는 제외한다.

**판정 기준 동일**: 주간 물량과 순기여를 실측한 뒤 편입 여부를 정한다.

**화면 배치**는 6단계 때 안을 만들어 제안한다 — 기사 탭 안에서 구분할지, 별도 "국내 동향" 탭을 둘지.

### 7단계 — 소스 확장 조사 (착수는 6단계 이후)

**목표**: 사내 게시판이 지금 안 보고 있는 곳에서 ITS 발주를 찾아낸다.

**후보 두 축**

- **MDB 나머지**: AIIB, AfDB(아프리카개발은행), IsDB(이슬람개발은행), CAF 등. 기존 2차 목록(IDB·EBRD·EIB)과 같은 방식으로 실측
- **국가별 조달포털**: 후보 국가는 두 신호로 고른다
  - (a) 게시판 기등록 400건의 국가 분포에서 역산한 관심 국가
  - (b) ITS 발주가 큰 시장 — 중동(UAE·사우디), 인도, 동남아, 영어권(영국·호주·캐나다·싱가포르)

**후보별 실측 항목** (기존 방식 그대로)

- 인증 없이 API/RSS 접근이 되는가
- 교통·ITS 필터가 **서버측**에서 되는가
- 주간 물량과 그중 ITS 건수
- 언어(영어 제공 여부), 봇 차단·안정성

**판정 기준은 "순기여"다.** 기존 소스(TED·World Bank·SAM.gov·ADB)와 겹치지 않는 ITS 건이 주당 몇 건 나오는가. TED(주 30건)를 기준선으로 삼고, 순기여가 낮으면 편입하지 않는다. 국가 포털은 언어·봇차단·인증 문제가 많으므로 **"다 붙이기"가 아니라 "조사 먼저 → 가성비 상위 2–3개만 편입"**이다.

**산출물**: 후보별 실측 표 + 편입 추천 2–3개 + 근거.

## 7-1. 작업 규칙 — 단계마다 자가검증

소스를 추가하거나 수집을 실행한 뒤에는 아래를 **직접 수행하고 결과를 보고한 뒤**에만 다음 단계로 간다. "됐다"만 보고하는 것은 금지.

1. **스키마 자가검사** — 전 항목 대상. 필수 필드(`id`·`kind`·`source`·`title`·`link`·`published`) 빈 값 개수, 날짜 형식 오류, 마감일이 이미 지난 발주 건수, `score` 분포(전부 0점이면 채점기 고장)
2. **표본 원문 대조** — 무작위 5건의 원문 링크를 실제로 열어 제목·국가·마감일이 원문과 일치하는지 확인. 링크가 죽었거나 내용이 다르면 그 소스 파서는 **불합격**
3. **관련성 눈검사** — 점수 상위 10건의 제목을 직접 읽고 관련/애매/무관으로 분류. 무관이 3건 이상이면 채점기를 고치고 다시 돌린다
4. **중복 검사** — 같은 실행 안 중복 0건인지, 재실행해도 `first_seen`이 처음 값으로 유지되는지
5. **보고 형식** — 합격/불합격 + 근거 수치 + 표본 5건 + 발견한 문제와 조치

**문제를 하나도 발견하지 못한 보고는 검증을 안 한 것으로 간주한다.**
